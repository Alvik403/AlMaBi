# 02. Архитектура приложения

## 2.1. Общая схема

```
┌──────────────┐        HTTP (реком. HTTPS)       ┌─────────────────────────────┐
│  Браузер     │ ───────────────────────────────► │  Reverse proxy (рекоменд.)  │
│  (UI)        │ ◄─────────────────────────────── │  nginx / traefik + TLS      │
└──────────────┘                                   └──────────────┬──────────────┘
                                                                  │ :18001
                                                       ┌──────────▼──────────┐
                                                       │  Docker: web        │
                                                       │  uvicorn + FastAPI  │
                                                       │  container:         │
                                                       │  dashboard_web      │
                                                       └──────────┬──────────┘
                              ┌────────────────┬──────────────────┼────────────┐
                              ▼                ▼                  ▼            ▼
                        templates/       static/dist/      uploads/almabi/   logs/
                        (Jinja2)         (Vite build)     (Excel)           runtime/
```

## 2.4. Поток обработки (просмотр «Тест BI»)

```
1. SessionMiddleware → cookie-сессия с путями загруженных файлов
2. resolve_almabi_test_dashboard_data()
3. run_test_pipeline / build_test_facts
      ├─ parse exports
      ├─ doc_tax / realization / cost joins
      ├─ tax_bucket, storno/NU split для прочих
      └─ Fact-строки
4. dashboard_builder → свод, фильтры, drill, графики
5. Jinja2 TemplateResponse
```

## 2.5. Поток загрузки Excel

```
POST /api/almabi/files/upload        (автоопределение типа)
  или
POST /api/almabi/files/upload-set    (buh + realization + cost [+ plan])
  → проверка расширения .xlsx
  → запись в uploads/almabi/{type}-{uuid}.xlsx
  → validate_almabi_export()
  → обновление session (almabi_upload_set / almabi_plan_forecast)
```

## 2.6. Сессии

- Выбор загруженных файлов хранится в **signed cookie-сессии** (`SESSION_SECRET`).
- Набор файлов действует **только для текущего браузера/сессии**.
- Глобального реестра «последней версии для всех пользователей» нет.
