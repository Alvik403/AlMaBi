# 05. Модель данных Excel и P&L

## 5.1. Входные выгрузки

| Тип | Ключ | Обязательность | Маркеры заголовков (упрощённо) |
|-----|------|----------------|--------------------------------|
| Бух.регистр | `buh` | Да | документ + сумма + счет дт |
| Реализация | `realization` | Да | выручка + (номенклатура / заказ клиента / группа проектов / направление) |
| Себестоимость | `cost` | Да | продукция / документ отгрузки + колонки себестоимости |
| План / прогноз | session `almabi_plan_forecast` | Нет | сумма + месяц + план/прогноз |

Формат: только `.xlsx`. Тип определяется по заголовкам (первые ~40 строк) и эвристикам имени файла.

## 5.2. Бух.регистр → `BuhRow`

Основные поля: документ, счет Дт/Кт, сумма БУ, суммы НУ Дт/Кт, месяц, вид налогообложения, статья расходов, договор, проект, номенклатура Кт, контрагент.

Особенности PQ:

- skip ≈ 8 строк заголовка, последняя служебная строка отбрасывается;
- вид налогообложения извлекается из субконто (приоритет PQ);
- статья прочих доходов/расходов — из субконто стороны 91.01 / 91.02.

## 5.3. Реализация → `RealizationRow`

Поля: документ, номенклатура, проект, группа проектов, направление, выручка, месяц, договор.

## 5.4. Себестоимость → `CostRow`

Поля: документ, номенклатура (продукция), счет, статья калькуляции, количество продаж, сумма, месяц, раздел себестоимости, аналитика, договор.

Разделы (PQ): при счёте ≠ 20 — «Прочие производственные расходы»; для счёта 20 — материалы / ФОТ / аренда / амортизация / ОПЗ и др. по статье калькуляции.

## 5.5. План / прогноз

Обязательные нормализованные заголовки: сумма, месяц, план/прогноз.  
Опциональные измерения: направление, группа, проект, вид налогообложения, раздел, вид себестоимости.

Без файла план/прогноз сценарии могут аппроксимироваться коэффициентами от факта (см. `almabi_mock_data.SCENARIOS`).

## 5.6. Поток построения фактов («Тест BI»)

```
parse exports
  → индексы doc_tax / doc_contract / doc_contractor
  → project_index + realization_lookup + cost PQ lookup
  → classify_buh_section → signed amounts → Fact
  → (прочие) storno / NU split при расхождении БУ и НУ
  → dashboard / reports
```

### Join (кратко)

1. Налог документа (`doc_tax`): льготный приоритетнее; выручка 90.01.3 может перезаписать.
2. Себестоимость: ключ `(document_match_key, nomenclature)`.
3. Реализация: договор+номенклатура → договор → документ+номенклатура → документ.
4. Аналитика: coalesce cost/realization → при конфликте realization → fallback project_index.
5. Fallback: если из буха нет выручки/себестоимости — дополнение из файлов реализации/себестоимости.

### Знаки сумм

- Выручка / прочие доходы: положительные.
- Себестоимость / коммерческие / управленческие / прочие расходы: отрицательные (как в PQ «Свод_нов»).

## 5.7. Налоговые корзины (`tax_bucket`)

| Условие | Корзина |
|---------|---------|
| «общие условия» / пусто | Нельготные проекты |
| льгот*, пониженн*, ставка 0, эконом. зона, … | Льготные проекты |
| Иное | Нельготные проекты |

UI-фильтр: Все виды / Льготные / Нельготные (+ направление, группа, проект, договор, контрагент, квартал, месяц).

## 5.8. Формулы свода P&L

Сценарии: `Факт БУ`, `Факт НУ`, `План`, `Прогноз`.

```
Операционная прибыль
  = Выручка + Себестоимость + Коммерческие + Управленческие

Прибыль/убыток до налогообложения
  = Операционная + Прочие доходы + Прочие расходы

Налоги (расчёт)
  = −base × rate
  rate = 0.02 если вид содержит «льгот», иначе 0.25
  (база — по НУ компонентам PBT в разрезе месяц × вид НО)

Чистая прибыль
  = PBT + Налоги
```

Замечание: для отображения выручки сценарий «Факт БУ» может брать НУ-суммы (`always_nu`).

## 5.9. Иерархия drill-down

```
Выручка / Себестоимость:
  KPI → направление → группа проектов → проект → договор

Льготные / прочие статьи:
  KPI → tax_bucket → [статья] → договор
```

## 5.10. Прочие доходы/расходы: storno и split БУ/НУ

- Документы, где |БУ| и |НУ| > 0.01 и различаются → `nu_mismatch_docs`.
- Storno-группы по `(document, section, round(|amount|, 2))`.
- Общая налоговая сторно-строка может наследовать льготный НО от зеркальной проводки.
- Если корзина налога БУ ≠ НУ → две Fact-строки (БУ-only и НУ-only).
